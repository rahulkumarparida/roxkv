NAME
       roxkv - lightweight in-memory key-value database with persistence,
       TTL support, logging, and history tracking.

SYNOPSIS
       set <key> <value...>
       set <key> <value...> --ttl <number> <sec|min|hr>

       get <key>

       del <key>

       save

       load

       keys

       history
       history --success
       history --error
       history --info

DESCRIPTION
       RoxKV is a simple key-value database written in Go. Data is stored
       in memory for fast access and can be persisted to disk using the
       SAVE command. RoxKV also supports automatic key expiration through
       TTL values and maintains an operation history log.

COMMANDS

       set <key> <value...>
              Creates a new key or updates an existing key with the
              provided value.

              Values may contain multiple words and can be enclosed in
              single quotes (' '), double quotes (" "), or backticks (` `)
              to preserve spaces.

              Examples:
                  set username rahul
                  set game "Battlefield 4"
                  set quote 'Never stop learning'


       set <key> <value...> --ttl <number> <sec|min|hr>
              Stores a key with an expiration time.

              After the specified duration expires, the key is
              automatically removed by the background expiry worker.

              Supported time units:
                  sec     Seconds
                  min     Minutes
                  hr      Hours

              Examples:
                  set otp 1234 --ttl 30 sec
                  set session abc123 --ttl 10 min
                  set token xyz --ttl 1 hr


       get <key>
              Retrieves the value associated with the specified key.

              If the key does not exist, RoxKV returns nil. If the key
              has expired, it is removed automatically and an expiration
              message is displayed.

              Examples:
                  get username
                  get game


       del <key>
              Deletes a key from memory.

              If the key exists, it is removed immediately. If the key
              does not exist, an informational message is logged.

              Examples:
                  del username
                  del otp


       save
              Persists all currently loaded keys to disk.

              RoxKV writes the in-memory snapshot to a date-based storage
              file. Existing data from previous snapshots is preserved.

              Examples:
                  save


       load
              Loads previously saved keys from disk into memory.

              During loading, RoxKV processes stored data from older
              snapshots to newer snapshots, ensuring that the latest
              version of a key is restored.

              Examples:
                  load


       keys
              Lists all currently available keys stored in memory.

              Useful for inspecting the active dataset and verifying
              successful loads or inserts.

              Examples:
                  keys


       history
              Displays all logged operations.

              The history log includes successful operations, informational
              messages, and error messages generated during database
              execution.

              Examples:
                  history


       history --success
              Displays only successful operations.

              Useful for auditing key creation, updates, persistence
              events, and database loading activities.

              Examples:
                  history --success


       history --error
              Displays only error entries.

              Useful for debugging parser issues, invalid command usage,
              failed persistence operations, and other runtime problems.

              Examples:
                  history --error


       history --info
              Displays only informational entries.

              Useful for all the operations performed by users.

              Examples:
                  history --info


FILES
       ~/.roxkv/roxdb/
              Contains persisted database snapshots.

       ~/.roxkv/roxlogs/
              Contains RoxKV log files organized by date.

BACKGROUND SERVICES
       Expiry Worker
              A background worker runs periodically and scans stored keys
              for expiration timestamps.

              Expired keys are automatically removed without requiring
              manual intervention.
