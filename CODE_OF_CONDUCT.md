# RoxKV Code of Conduct

## Our Commitment

RoxKV is an open-source project where people should be able to contribute, learn, discuss ideas, and improve the project in a respectful environment.

Everyone participating in the project is expected to treat other contributors professionally regardless of experience level, background, or technical opinion.

## Expected Behavior

Examples of positive behavior include:

* Being respectful during technical discussions.
* Giving constructive and specific feedback.
* Accepting constructive criticism.
* Helping contributors understand the project.
* Respecting different levels of experience.
* Focusing discussions on technical ideas rather than individuals.
* Acknowledging mistakes and correcting them.
* Keeping issues and pull requests relevant to the project.
* Giving credit when using another contributor's work or ideas.

Technical disagreement is completely acceptable. Personal attacks are not.

## Unacceptable Behavior

The following behavior is not acceptable:

* Harassment, threats, or intimidation.
* Personal insults or targeted hostility.
* Discrimination or derogatory comments.
* Repeated trolling or intentionally disruptive behavior.
* Publishing another person's private information without permission.
* Sexual harassment or unwanted sexual attention.
* Spamming issues, discussions, or pull requests.
* Deliberately disrupting development or community discussions.
* Impersonating contributors or maintainers.
* Knowingly submitting malicious code.
* Attempting to introduce backdoors, credential stealers, malware, or intentionally vulnerable code.
* Abusing project infrastructure or community resources.

Criticism of code is allowed and encouraged when constructive.

Criticism should address the implementation:

> This approach can cause a race condition when multiple clients modify the map.

rather than the contributor:

> You don't understand concurrency.

## Issues and Pull Requests

Issues and pull requests should remain focused on improving RoxKV and RoxAI.

Maintainers may close, edit, lock, or remove contributions that:

* are intentionally disruptive,
* contain harassment,
* repeatedly ignore contribution guidelines,
* contain malicious content,
* expose sensitive information,
* or are unrelated to the project.

A rejected pull request does not imply that the contribution or contributor is not valued. Technical decisions may be based on architecture, maintenance cost, performance, scope, compatibility, or project direction.

## AI-Generated Contributions

AI-assisted development is allowed.

However, contributors remain responsible for the code they submit.

Submitting AI-generated code without understanding or verifying it does not transfer responsibility to the AI system.

Contributors should:

* Review generated code.
* Verify that it actually works.
* Test relevant behavior.
* Check for security issues.
* Ensure licensing requirements are respected.
* Avoid fabricated APIs, dependencies, benchmarks, or test results.

Do not claim that code was tested when it was not.

## Security and Responsible Behavior

Do not intentionally submit:

* malware,
* backdoors,
* credential-stealing code,
* destructive payloads,
* hidden telemetry,
* intentionally vulnerable dependencies,
* or code designed to compromise contributors or users.

Security research intended to improve RoxKV is welcome when performed responsibly.

Potential vulnerabilities should be reported through the project's designated security reporting mechanism when one is available.

## Maintainer Responsibilities

Project maintainers are responsible for interpreting and enforcing this Code of Conduct.

Maintainers should apply moderation decisions based on behavior rather than personal disagreement.

Depending on the severity and frequency of a violation, maintainers may:

1. Issue a private or public warning.
2. Remove or edit inappropriate content.
3. Close or lock discussions, issues, or pull requests.
4. Temporarily restrict participation.
5. Permanently ban participation in project spaces.

Serious malicious or threatening behavior may result in immediate removal without prior warning.

## Scope

This Code of Conduct applies to official RoxKV project spaces, including:

* repository issues,
* pull requests,
* discussions,
* code reviews,
* project-maintained communication channels,
* and other spaces where someone is representing the project.

## Reporting Problems

If you experience or observe behavior that violates this Code of Conduct, report it privately to the project maintainers using the contact or reporting mechanism provided by the repository.

Reports should include relevant context where possible.

Maintainers should handle reports responsibly and avoid unnecessarily exposing information about the reporter.

## Final Principle

RoxKV exists to build, experiment, and learn.

Challenge implementations. Question architectural decisions. Debate trade-offs.

Respect the people behind them.
